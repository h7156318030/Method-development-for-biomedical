# MethodFlow 计算机化系统验证（CSV）模板

> 本目录提供**起点模板**，不是已完成的验证。MethodFlow 本身不是“已验证的 GxP 系统”；
> 在受监管的实验室使用前，使用单位须按自己的 SOP 完成风险评估、IQ/OQ/PQ 并由质量部门批准。
> 自动测试（`tests/`，URS 追溯见 `docs/URS_需求与测试追溯.md`）可作为 OQ 的支持证据，但不能替代执行记录。

## 1. 风险评估（示例，需按本单位情况修改）

| 功能 | 对数据完整性/患者安全的影响 | 概率 | 可检测性 | 风险等级 | 控制措施 |
|---|---|---|---|---|---|
| 电子签名与阶段锁定 | 高 | 低 | 高（审计追踪） | 中 | OQ 测试 URS-3x/5x；审计追踪审核 |
| 审计追踪（哈希链） | 高 | 低 | 高 | 中 | 定期审核（URS-154）；备份 `data/` |
| 判据自动判定 | 中 | 中 | 中（人工复核） | 中 | 人工判定不同时警示；第二人复核 |
| 统计计算器 | 中 | 中 | 中 | 中 | 对照独立计算（如已验证的统计软件）核对一组样例 |
| 文档导出 | 中 | 低 | 高（人工审阅） | 低 | 正式签发前人工审阅 |
| 备份/恢复 | 高 | 低 | 中 | 中 | 定期恢复演练 |

## 3. OQ（运行确认）清单

对每条 URS 执行并记录：运行 `python -X utf8 -m unittest discover -s tests`，保存输出；
对自动测试未覆盖的界面行为（英文界面、文档外观、浏览器兼容）逐项手工目检并截图。

| 编号 | 场景 | 预期 | 实际 | 通过 |

| OQ-3 | 提交人不能自己签署 | 被拒绝 | | |

## 4. PQ（性能确认）

在真实使用场景下，用一个已完成的历史方法开发案例（脱敏）端到端录入，
由使用者确认：流程可用、判据判定正确、文档满足内部审阅要求。记录偏差及处理。

## 5. SOP 草稿要点

1. 目的与范围（方法开发记录的电子化管理）。
2. 角色：管理员、批准人、复核人、贡献者；职责分离规则。
3. 账号管理：创建、停用、密码有效期、离职处理。
4. 日常操作：新建项目/方法、阶段提交与签署、偏离处理、修订已批准方法。
5. 数据完整性：审计追踪审核频次（默认 90 天）、备份与恢复演练、检查包导出。
6. 变更控制：升级前备份；升级后重跑自动测试并记录。
7. 已知限制：见 README 与《ROADMAP.md》。
