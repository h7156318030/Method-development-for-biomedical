# 后端加固清单（来自独立审查 + 运维检查）


## 高危
**H1 职责分离可绕过**
- stages 增加累计的 `contributors`（不因撤回/退回/修订递增而重置）；提交人、保存人、实验编辑人都计入；`_eligible`、`pending_role_for` 用 contributors 而不是 editors。`editors` 可保留作“当前修订的编辑者”显示。
- `set_members` / `create_project`：项目角色必须匹配全局角色（reviewer 需全局 reviewer，approver 需全局 approver，owner/author 需全局 author 或 admin）；同一用户在同一项目不得同时拥有 {owner,author} 与 {reviewer,approver} 两类；存在 `in_review` 阶段时不得增删 reviewer/approver 成员。reviewer 与 approver 不得为同一人（一个人不能同时占两个签署角色）。
**H2 实验绕过锁**
- `stage_key` 一旦设置不可置空；改派到别的阶段时，新旧阶段都必须可编辑且存在；`delete_attachment` 同时检查附件所属实验的锁；`_touch_editor` 不得修改锁定阶段。
**H3 签名哈希未覆盖实验与附件**
- 把实验的 code/title/objective/design/acceptance（以及对 explore/robust/control/report 各自门：该阶段实验的 results/conclusion/deviations/status）和该阶段/实验的附件 sha256 列表纳入 `stage_hash`（GP 门覆盖所有实验的设计与接受标准）。方案批准后：实验 title/objective/design/acceptance 冻结（409，提示“需先重新打开方案阶段，或在偏离/说明中记录”）；方案批准后新增实验允许但标记 `added_after_plan=1`，文档中单列“方案外追加”，不影响 GP 哈希（GP 哈希只含方案批准时点已存在且未标记追加的实验）。项目元数据（title/product/attribute/intended_use）并入覆盖 charter 的门的哈希；任一阶段已批准/完成后，这四项不可改（409）。
**H4 篡改检测**
- `intact` = 当前修订下重算 `stage_hash` 与评审记录哈希比较；历史修订对照 stage_revisions。`docgen.generate()`：任一已批准阶段签名完整性失败 → 状态标记“完整性校验失败”，不得标“已批准版本”，并在文档首页红字提示。`audit.verify` 扩展：返回 `signatures_ok`/`bad_signatures` 列表（遍历所有 approved/completed 阶段）；在 `/api/audit/verify` 一并返回。
**H5 签名绑定所见内容**
- review 请求必须带 `revision` 与 `expected_hash`（前端取自 stage_detail 的 `revision`、`hash`）；事务内与当前值比较，不一致 409“内容已更新，请刷新后重新审阅”。缺字段 400。

## 中危
- **M1** audit_log / reviews / stage_revisions 加 `BEFORE UPDATE/DELETE … RAISE(ABORT)` 触发器（reviews 需保留合法的内部流程更新则只禁删除并禁改关键列）；审计链头（id、count、hash）写入 `data/audit_head.json` 并随每次备份写入备份旁注文件；verify 比较 count 不得小于锚点且锚点 hash 必须在链中；用 HMAC-SHA256（密钥生成于 `data/.audit_key`，首次启动随机生成，权限尽量收紧）替代裸 SHA-256（需兼容：版本号字段区分旧链，旧库首次启动做一次性迁移或链内“v2 起点”标记）。
- **M2** 所有写操作（实验增改删/状态、附件上传删除、复核、撤回、提交……）统一检查项目 `status=='active'`（`require_active_project`）；项目状态回退（completed/archived/cancelled→active）需 reason + 密码重认证；`update_project` 校验字符串非空且类型正确。
- **M3** `must_change` 在 `current_user` 中强制：仅允许 `/api/me`、`/api/me/password`、`/api/logout`，其余 403 `{"error":"须先修改密码","must_change":true}`；改密码后删除该用户其他会话；`change_password` 接入失败计数与锁定。
- **M4** 登录：未知用户也执行假 bcrypt 比对；锁定/停用/错密码返回同一通用错误（锁定可返回 429 + 通用文字，但不得区分用户是否存在）；先验密码再看状态；按用户名+来源 IP 限速；未知用户的失败审计按 (username, 窗口) 去重。
- **M5** 上传：端点改为 sync def 或流式；先校验成员与编辑权限与 `Content-Length` ≤ max_upload_mb，再流式写临时文件并计数超限即中止；全局请求体大小中间件（JSON 接口上限 20 MB）；`current_user` 不应在 async 路径上阻塞（见 L10）。
- **M6** 备份：校验 `PRAGMA integrity_check`；启动备份与每日备份分开保留；写入 uploads/documents 的 sha256 清单（manifest）到备份旁注；`tools/backup.py --files` 保持可用。
- **M7** docgen：`_cell_text`/`_para` 去除 XML 非法控制字符；矩阵权重/分数 `float()` 容错；FMEA S/O/D 保存时夹到 1–10 整数并拒绝异常值；图表改用 `matplotlib.figure.Figure`（非 pyplot，线程安全）；文档生成放在写事务之外或至少不在持锁时渲染图表。
- **M8/L1** 对 `sections`、`checklist`、实验字段、成员、项目字段做结构与类型校验（按章节定义：text→str 限长；fields→dict；table→list[dict]；matrix→dict；fmea→list[dict]）；全局异常处理器把 TypeError/ValueError/AttributeError/KeyError/OverflowError 转成 400 JSON（不泄露堆栈）；`users_create/patch` 校验字符串与 roles 为 list[str]。

## 低危
- L2 实验 `owner_id` 须为项目成员；L3 `limit` 夹到 [1, 2000]；L4 stale 传播取传递闭包；L5 同 L1；L6 `init_db` 事务化并加迁移钩子（user_version 递增框架）；L7 cookie 加 `max_age`（=session_hours）、host 非本机时加 `Secure`，增加 CSP（`default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:`），Host 头校验（可配置 allowed_hosts）；L9 `/api/users` 非 admin 仅返回在用账号的 id/display_name/roles（不含 username 可保留）；L10 `current_user` 用只读连接，`last_seen` 节流写（>60 s 才写）；L11 生成文档需编辑权限（owner/author/reviewer/approver/admin，不含 viewer），并限制同项目每分钟 6 次；L13 登录时清理过期会话；L14 见 H3。
- 运维检查发现：`/api/setup` 初次设置建议支持 `config.json` 的 `setup_token` 可选项（设置了则必须提供）；`users_patch` display_name 非字符串 500（并入 L1）；提供离线管理员重置密码工具 `tools/reset_admin.py`（需停服务，写审计，生成临时密码并强制修改）。

## 约束
- 不改变前端已依赖的响应字段（见 docs/前端契约.md 与 stage_detail/project_detail/dashboard 现有字段，只能新增）；新增字段：stage_detail 增加 `contributors_names`、`signatures_ok`；dashboard 不变。
- 文件内容用 Write/Edit 工具写（bash/python heredoc 会弄乱中文）。
