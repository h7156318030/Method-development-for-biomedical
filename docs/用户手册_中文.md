# MethodFlow 使用手册（V0.4）

分析方法开发全流程管理。把“项目”（产品/管线层面的容器）和“方法”（一个具体的分析方法）分开管理；每个方法按 9 个阶段推进，在评审门上强制复核/批准并留下电子签名，所有操作进入防篡改检测的审计追踪；最后一键生成可直接送审的《分析方法开发方案》《分析方法开发报告》（Word + PDF）。

> **使用前请先读第 17 节“局限与合规声明”。本程序不是已验证的 GxP 系统：用于受监管用途须由企业 QA 按 CSV/GAMP 5 流程评估，补充 IQ/OQ/PQ、SOP、账号管理、备份与灾难恢复、电子签名法规符合性评估。模板里的数值是示例，法规条款标“条款待核对”的须逐条核实。**

相关文档：`docs\V0.2需求与设计_项目方法分离与审批级文档.md`（V0.2 设计）、`docs\前端契约.md`（v2 接口说明）、`docs\URS_需求与测试追溯.md`（需求与测试对应关系）、`docs\自动化测试报告.md`（最近一次测试结果）、`docs\调研与设计依据.md`、`docs\后端加固清单.md`。

## 1. 它解决什么问题

- **项目与方法分开**：一个项目（如“XX-CAR-T 分析方法包”）下可以有多个方法（如“CD19/CD22 双靶点流式检测法”“残留 DNA qPCR 法”），各自走完整的开发流程。
- **9 个阶段 + 6 个评审门**：从分析目标概况（ATP）到“进入验证”的批准，按 ICH Q14 / Q2(R2) 的思路组织；评审门上必须有人复核/批准，签名要重新输入口令，并与签名当时的数据内容绑定。
- **职责分离**：编辑过内容的人不能复核/批准同一内容，复核人与批准人分开。
- **审计追踪**：每次保存、提交、签名、重新打开、生成文档都有记录，记录之间用哈希链接，可检测篡改；附件带 SHA-256。
- **审批级文档**：模板驱动，生成带封面、修订历史、目录、签署页、页眉页脚的 Word，并转换为 PDF；未批准内容自动标“草稿”。
- **7 种方法类型模板**：流式细胞术、色谱（HPLC/CE/GC）、生物活性（相对效力）、细胞法功能/效力、qPCR/ddPCR、ELISA/SPR 等免疫化学/结合法、通用；每个模板预置术语、参考文件、试剂仪器、方法条件、FMEA（12 条）、实验（11–13 个）、SST 与检查清单。
- **知识库**：把经验、陷阱、审评缺陷写入知识库，新方法按技术类型和阶段自动推送。
- 数据存在本机，**启动时和每 24 小时自动备份**。

## 2. 快速开始

**环境**：Windows，Python 3.9 及以上（可用环境变量 `METHODFLOW_PYTHON` 指定 python.exe 路径）。要输出 PDF 还需安装 LibreOffice（见第 7 节，不装也能用，只是没有 PDF）。

1. 双击 `start.bat`（或在命令行执行 `python run.py`）。
   - 依次查找 `METHODFLOW_PYTHON`（如已设置）、`py -3`、`python`；
   - 缺少依赖时会询问是否执行 `pip install -r requirements.txt`（需要联网或内部镜像）；
   - 服务启动后**自动打开浏览器**，地址 `http://127.0.0.1:8780/`。
2. **首次访问：没有任何预设账号或密码。** 页面会进入“初始化”界面，由你创建第一个管理员账号：用户名（3–32 位，字母/数字/`_.-`）、姓名、口令（**至少 10 位，且同时含字母和数字**）。若部署时在 `config.json` 里设置了 `setup_token`，初始化页会多一个输入框，须填入同一个初始化口令，否则创建被拒绝（防止别人抢先初始化，见 11.3）。这个首个账号同时拥有“管理员、开发人员、复核人、批准人”四种全局角色，创建后立即登录。
3. 登录后，到 **管理 → 用户管理** 为同事创建账号并分配全局角色。新建账号首次登录必须修改口令。**务必创建多个账号**：评审门要求复核人/批准人不是内容的编辑者，一个人无法自己通过自己的评审门。**建议至少保留两个管理员账号。**
4. 关闭：关闭 `start.bat` 的黑色窗口（或按 Ctrl+C）。关闭期间无法访问，数据不受影响。

命令行参数（`start.bat` 后面的参数会原样传给 `run.py`）：

```
python run.py                     # 使用 config.json / 默认值（127.0.0.1:8780，数据在 .\data）
python run.py --port 8790         # 换端口
python run.py --data D:\mf_data   # 换数据目录
python run.py --no-browser        # 不自动打开浏览器
python run.py --host 0.0.0.0      # 局域网访问，先读第 12 节
```

优先级：命令行参数 > 环境变量（`METHODFLOW_DATA`、`METHODFLOW_HOST`、`METHODFLOW_PORT`）> `config.json` > 内置默认值。

## 3. 核心概念

### 3.1 项目（Project，编号 `PRJ-年份-序号`）

产品/管线层面的工作容器：名称、产品、适应症、研发阶段、起止日期、状态（进行中 / 暂停 / 完成 / 归档）、项目负责人和项目团队。一个项目下有 0 到多个方法。

**项目团队角色**（一人只有一个）：

| 角色 | 权限 |
|---|---|
| 项目负责人（owner） | 修改项目信息与状态，调整项目团队，新增方法，调整所属方法的团队 |
| 项目成员（member） | 可新增方法（还须具备全局“开发人员/管理员”角色），可查看项目下全部方法 |
| 只读（viewer） | 只能查看项目及其下方法 |

- 新建项目需要全局角色“开发人员”或“管理员”，创建者自动成为项目负责人。
- 项目状态改为“完成”要求项目下没有进行中的方法；把非“进行中”的项目改回“进行中”要填原因并输入口令。
- 项目暂停/归档后，其下方法不可再修改（可读、可生成文档）。
- 项目下任一方法的任一阶段已批准后，项目的“产品”字段冻结。

### 3.2 方法（Method，编号 `AM-年份-序号`）

一个具体的分析方法：名称、所属项目、技术类型（模板）、被测属性、样品基质、预期用途、方法版本（如 V0.1）、生命周期、开发状态（进行中 / 完成 / 归档 / 取消）、方法负责人和方法团队。9 阶段流程、实验、附件、评审、审计和文档全部属于方法。编号在全局按年份顺序排，与项目无关。

**方法团队角色**（一人可兼多个，但有下面的限制）：

| 角色 | 权限 |
|---|---|
| 方法负责人（owner） | 编辑内容；修改方法信息/状态；调整方法团队；重新打开已通过阶段；变更生命周期 |
| 开发人员（author） | 编辑阶段内容、登记/编辑实验、上传附件、提交/撤回、登记经验 |
| 复核人（reviewer） | 复核签名（须满足职责分离） |
| 批准人（approver，QA） | 批准签名；重新打开已通过阶段；变更生命周期 |
| 只读（viewer） | 只能查看 |

**谁能看到方法**：方法团队成员 ∪ 所属项目的任意成员 ∪ 管理员。**谁能编辑/签名**：只看方法团队角色，项目角色不起作用。**方法团队成员必须先是所属项目的成员**（管理员除外），方法角色必须与其全局角色匹配（负责人/开发人员需要全局“开发人员”或“管理员”；复核人/批准人需要对应的全局角色）。

**生命周期**（方法的一个状态字段）：开发（development）→ 验证（validation）→ 转移（transfer）→ 常规使用（routine）→ 停用（retired）。V0.2 只提供“开发”阶段的完整流程；其余生命周期阶段只是手动记录：方法负责人或批准人在方法页执行“变更生命周期”，填写原因并输入口令，写入审计（`method.lifecycle`）。验证、转移等流程模板留待后续版本。

**克隆**：可把方法克隆到同一项目或另一个项目（目标项目的权限要求同新增方法）。克隆复制被测属性、基质、用途和各章节内容，检查清单重置为未完成，**不复制签名、团队（只有创建者）、实验及结果**。

### 3.3 九个阶段与评审门

| # | 阶段（key） | 评审门 | 谁签名 | 前置阶段 |
|---|---|---|---|---|
| 1 | 立项与背景（charter） | 无（提交即“已完成”） | — | — |
| 2 | 分析目标概况 ATP（atp） | **G1 ATP 复核** | 复核人 | 1 |
| 3 | 技术选择与试剂策略（tech） | **G2 技术与试剂复核** | 复核人 | 2 |
| 4 | 风险评估 FMEA（risk） | 无（提交即“已完成”） | — | 2 |
| 5 | 开发方案与实验设计（plan） | **GP 开发方案批准** | 复核人 → 批准人 | 3、4；同时覆盖 1–4 |
| 6 | 可行性与优化实验（explore） | **G3 可行性复核** | 复核人 | 5 |
| 7 | 稳健性、稳定性与参数范围 DoE（robust） | 无 | — | 6 |
| 8 | 参比品与控制策略（control） | **G4 控制策略复核** | 复核人 → 批准人 | 7；覆盖 7 |
| 9 | 预验证与开发报告（report） | **G5 进入验证批准** | 复核人 → 批准人 | 8；覆盖 6、7、8 |

- “前置阶段”未通过或已失效时，后一阶段不能提交。
- “覆盖”表示签名时同时绑定被覆盖阶段的内容哈希；被覆盖阶段未通过或已失效，该门不能提交。
- 阶段状态：未开始 → 进行中 → 待复核 → 已通过（有评审门）/ 已完成（无评审门）；复核人退回则为“已退回”，修改后再提交。
- 提交前系统做检查：缺必填内容、前置阶段未通过、实验未关闭、没有可用复核人/批准人、FMEA 高风险无控制措施、检查清单“需留证据”的项没写说明等都会阻断，页面会逐条列出。数字判据缺失等只是警告。

### 3.4 职责分离与贡献者

- **贡献者**：保存过该阶段内容、提交过该阶段、编辑过其下实验、上传/删除过其下实验附件的人。**贡献者永远不能复核/批准该阶段**（即使后来被调出开发人员角色）。
- 两步门（GP/G4/G5）必须**先复核人、后批准人**，且复核人和批准人不能是同一个人；同一人不能同时是（负责人/开发人员）和（复核人/批准人）。
- 提交时如果方法团队里没有符合条件的复核人/批准人，系统直接阻止提交并告诉你缺什么。
- 有阶段待复核时，不能增删复核人/批准人。

### 3.5 电子签名

复核/批准（通过或退回）以及“重新打开”“变更生命周期”“把方法/项目改回进行中”都要**再次输入当前口令**。签名记录保存：姓名、时间（UTC）、角色、签名含义（如“复核：我已审阅本阶段内容，确认其完整、准确并符合方案要求”）、意见，以及**签名时的修订号和内容 SHA-256 哈希**。

- 提交时先给内容拍快照；签名请求必须带上审阅时看到的**修订号和哈希**，服务器核对当前值，不一致就拒绝（“内容已更新，请刷新后重新审阅”）。
- 哈希覆盖阶段内容、该阶段的实验与附件、以及方法与项目的基本信息；事后有人在数据库里改了这些，签名的“完整性”标记会变为失败，并出现在方法页、文档和管理页的校验里。
- 口令错误会进入审计并计入锁定次数。

### 3.6 锁定、重新打开与“已失效”

- 阶段通过后**锁定**：不能再改内容、实验、附件。方案批准后，方案内实验的标题/目的/设计/接受标准也不能改、不能删。
- 要改只能“**重新打开**”（填原因 + 口令；方法负责人或批准人执行）：该阶段回到“进行中”，修订号 +1；所有依赖它的**已通过**阶段被标为“**已失效（stale）**”，**待复核**的被退回。已失效阶段不算通过，下游阶段和评审门不能提交，生成的文档也是草稿。
- 上游重新通过后，对已失效阶段用“**重新提交复核**（recertify）”：内容不变也要重新复核、重新签名。
- 退回、撤回、重新打开都产生新修订，旧修订的签名保留在历史中。
- 多人同时编辑同一阶段时，后保存的人会收到“版本冲突”，请刷新后重新修改。

### 3.7 示例值警告

模板里的判据和实验接受标准带有“（示例值，须按ATP确认）”标记。**开发方案（plan）和报告（report）阶段提交前，只要阶段数据或未取消实验的接受标准里还留着这个标记，就会出现警告**（含数量）。这只是警告，不阻断提交；但请按 ATP 把数值确认后删去标记，否则就是把示例值当成了批准的判据。

## 4. 典型流程（一个新方法从头走一遍）

1. **准备账号**（管理员）：管理 → 用户管理，创建开发人员、至少一名复核人、至少一名批准人(QA)。
2. **新建项目**：菜单“项目”→“新建项目”，填名称、产品、适应症、研发阶段、起止日期，并添加**项目团队**（负责人/成员/只读）。编号自动生成 `PRJ-年份-序号`。
3. **添加团队**：方法的复核人、批准人必须先是项目成员，所以先在项目页的“团队”里把他们加进来。
4. **用模板新建方法**：在项目页点“新增方法”（或“方法”→“新建方法”并选项目）。选**方法类型模板**（可看到模板的更新记录和预置数量），填方法名称、被测属性、样品基质、预期用途、方法版本、计划开始，并从项目成员里指定**方法团队**：开发人员、复核人、批准人。创建者自动成为方法负责人 + 开发人员。系统建立 9 个阶段，预置 ATP 判据、技术评分矩阵、FMEA、实验与 SST 草稿，以及各章节的示例文字。
5. **逐阶段填写**：阶段页的每个章节标注了在方案/报告中的章号；写作要点和示例在“帮助/占位提示”里；检查清单逐项完成。必填项未填会在“提交前检查”里列出。
6. **立项与背景** → 提交 → 无评审门，直接“已完成”。
7. **ATP** → 提交 → 复核人在页面上“通过/退回”并输入口令签名（G1）。判据建议用统计区间表达，不含数字的判据会给出提示。
8. **技术选择**：填评分矩阵与试剂策略 → G2 复核。**风险评估 FMEA**：填 S/O/D（1–10）；RPN ≥ 120 或 S ≥ 8 的失效模式**必须**写控制措施（阈值可配置）→ 提交即完成。
9. **开发方案**：在“实验”页登记全部拟做实验，每个必须写**设计**和**接受标准**；填统计计划等 → GP：复核人先签，批准人后签。**方案提交或批准后再新增实验，也必须填写设计和接受标准**（否则无法新增），这类实验标记为“方案后新增”，在文档中单列。
10. **执行实验**：**方案批准后**才能把实验改为“进行中”；做完填**结论**才能标“已完成”；取消须写原因。结果表、偏离、原始数据附件随实验记录。
11. **可行性 → 稳健性 → 控制策略**：每个阶段提交前，其下所有实验必须已完成（有结论）或取消（有说明）。依次过 G3、G4。
12. **报告阶段**：对照 ATP 汇总结果、验证策略，沉淀经验教训 → G5 批准进入验证。
13. **生成文档**：在方法的“文档”页生成《方案》《报告》的 Word 和 PDF（见第 8 节）。随时可以生成：未全部批准时是“草稿”，批准后是“已批准版本”。
14. 方法负责人把方法状态设为“完成”（要求所有阶段已通过/完成且无失效），再按需变更生命周期为“验证”等；项目负责人在所有方法结束后把项目设为“完成”。可把经验教训写入知识库。

中途发现上游要改：用“重新打开”（见 3.6），按提示处理受影响的阶段。

## 5. 七个方法类型模板

模板版本 `1.1`，每个模板含更新记录（changelog）和预置内容统计。

| key | 名称 | FMEA 种子 | 实验种子 | SST 种子 |
|---|---|---|---|---|
| `flow` | 流式细胞术（CAR-T 表达/表型）：串色、FMO、事件数、保持时间、Fc 受体、WRM 等经验 | 12 | 12 | 8 |
| `hplc` | 色谱方法（HPLC/CE/GC：含量、纯度、杂质）：色谱条件、系统适用性、强制降解、峰纯度、积分规则 | 12 | 12 | 6 |
| `bioassay` | 生物活性测定（相对效力：4PL/平行线，蛋白药物）：参考品、相对效力、PAR | 12 | 11 | 6 |
| `cell_based` | 细胞法功能/效力测定（报告基因、杀伤、细胞因子释放） | 12 | 13 | 6 |
| `qpcr` | qPCR/ddPCR（VCN、残留 DNA、载体拷贝）：标准曲线/效率、NTC、抑制对照、LOD/LOQ | 12 | 13 | 6 |
| `elisa` | 免疫化学/结合法（ELISA、SPR、MSD）：包被/封闭/曲线拟合、平行性、钩状效应 | 12 | 13 | 6 |
| `generic` | 通用分析方法 | 12 | 13 | 4 |

每个模板预置术语表、参考文件（含文件编号/版本列）、关键试剂与仪器、初始方法条件表、ATP 判据行、技术评分矩阵、检查清单（含引用条款）、FMEA、实验（含设计与接受判据示例）和 SST。**所有数值都是示例，须按 ATP 确认；引用条款标“条款待核对”的须由使用方逐条核实原文。** 模板内容在创建方法时复制进方法，之后改模板不影响已有方法。

## 6. 文档：草稿、已批准与完整性

在方法的 **文档** 页生成：

## 7. PDF 输出（LibreOffice）

PDF 由 LibreOffice 把 Word 转换而来（`soffice --headless --convert-to pdf`）：

1. 安装 LibreOffice（<https://www.libreoffice.org>）。程序按这个顺序找 `soffice`：管理页设置的“soffice 路径”→ `config.json` 的 `soffice_path` → 系统 PATH → `C:\Program Files\LibreOffice\program\soffice.exe` 等默认安装位置。装在其他位置时，到“管理 → 文档设置”填写路径。
2. 转换需要系统里有中文字体（Windows 自带）。
3. **生成一份文档（含 PDF）约需 20–60 秒**，首次启动 LibreOffice 更慢；页面上按钮会显示“生成中，约需 20–60 秒…”，请不要重复点击。单次转换超过 `pdf_timeout_sec`（默认 120 秒）会放弃并只保留 Word。
4. 没装 LibreOffice、转换失败、超时或配置关闭（`pdf_enabled=false`）时，只生成 Word，页面提示原因，不算错误。
5. 为了让 PDF 的静态目录页码正确，转换会做两遍（用 `pypdf` 读取第一遍 PDF 的书签）；`pypdf` 在 `requirements.txt` 里。

## 10. 备份与恢复

- **自动备份**：程序启动时备份一次（标签 `startup`，保留 `backup_keep_startup` 份，默认 10），之后每 24 小时一次（标签 `daily`，仅程序持续运行时）；手动备份与自动备份共用 `backup_keep`（默认 30，按标签分组各保留 30 份）。
- **手动备份**：管理 → 数据备份 →“立即备份”，或双击 `backup.bat`（运行中也可执行；备份后立即校验完整性和审计链）。`python tools\backup.py --files` 还会把 `uploads` 和 `documents` 打成 `files_时间.zip`（不会被自动清理）。
- **务必另外备份这些文件**（`backup.py` 只处理数据库和 zip，**不会复制 `.audit_key`**）：`data\.audit_key`、`data\audit_head.json`，并把 `data\backups` 定期复制到另一块磁盘/网络位置。同盘备份挡不住磁盘损坏。
- **恢复**（先关闭 MethodFlow）：

  ```
  python tools\restore.py                       # 列出可用备份
  python tools\restore.py methodflow_20261014_093000_manual.db
  ```

  脚本会：①若服务器仍在运行则拒绝（启动时用了 `--port` 的话，恢复时加同样的 `--port`）；②校验备份（能打开、完整性检查、结构版本、审计链；缺 `.audit_key` 会明确提示），不通过则拒绝并不改动现有数据；③把当前数据库另存为 `data\backups\prerestore_时间.db`（可回退）；④替换数据库；⑤复检。`uploads` 与 `documents` **不会被改动**。恢复后重新启动，到管理页点“校验审计链与签名”，并抽查附件的“校验完整性”。
- **审计锚点**：`python tools\audit_anchor.py` 显示审计链、锚点与触发器状态。恢复旧备份或锚点丢失后，审计校验会报“锚点缺失/被改动”；确认审计链本身校验通过后，用 `python tools\audit_anchor.py --reset --yes` 以当前链头重建锚点（该动作本身写入审计）。`.audit_key` 丢失时无法重建，必须从备份取回。
- 恢复演练、保留期限、异地副本、灾难恢复时间目标等由企业制度规定。

| `lock_minutes` | `15` | 锁定时长（分钟） |
| `login_rate_max` | `10` | 同一“用户名 + 来源 IP”每分钟失败登录超过此数返回 HTTP 429 |
| `backup_keep` | `30` | 手动/每日/其他备份各保留的份数，更早的被删除 |

## 12. 多人局域网使用

默认只有本机能访问（`127.0.0.1`）。多人使用有两种做法：

- **推荐**：服务仍监听本机，另用 **HTTPS 反向代理**（Caddy、nginx、IIS + ARR 等）对外提供 `https://…`，代理转发到 `http://127.0.0.1:8780`；防火墙只放行代理端口；`config.json` 里设置 `"allowed_hosts": ["你的域名"]`（代理需要把原始 Host 头转发过来），并设置 `setup_token`。通过 HTTPS 访问时 Cookie 带 `Secure` 才有意义，此时应保持 `cookie_secure` 为 `true`（监听本机且走 HTTPS 代理时需手动设为 `true`）。
- **直接开放**：`config.json` 里设 `"host": "0.0.0.0"`（或 `python run.py --host 0.0.0.0`），Windows 防火墙放行 8780，同事访问 `http://服务器IP:8780/`。**注意：监听非本机地址时，`cookie_secure` 自动为 true，浏览器不会通过普通 HTTP 回传带 `Secure` 的 Cookie，登录会“成功但立刻掉线”。在纯 HTTP 下必须同时设置 `"cookie_secure": false`。**

**警告**：纯 HTTP 下口令和会话以明文在网络上传输；只应在受信任的内网、配合防火墙使用，不要暴露到互联网。服务器时钟是所有签名/审计的时间来源，请与时间服务器同步。MethodFlow 是单机 SQLite 程序，同时在线人数多时请评估性能；一台服务器只运行一个实例；服务器电脑必须保持开机并运行 `start.bat`。

### 13.2 新增方法类型（技术模板）

编辑 `app\templates_data.py` 中的 `TECHNIQUES` 字典，复制 `"generic"` 或 `"hplc"` 条目，用新的 key（只用字母数字）添加（下面只是键的清单，各键的行格式以现有条目为准）：

```python
TECHNIQUES["mykey"] = {
    "label": "界面里显示的名称",
    "desc": "一两句话说明适用范围",
    "changelog": [...],       # 本模板的更新记录
    "matrix": {"options": ["候选技术A", "候选技术B"],
               "criteria": [("满足ATP的能力", 5), ("通量", 2)]},          # (准则, 权重)
    "atp_rows": [...],        # ATP 判据行
    "extra_checklist": {"atp": [ck("my1", "检查项文字", "指导说明", "出处", True)],
                        "tech": [...], "plan": [...], "robust": [...], "control": [...]},
    "fmea": [...], "experiments": [...], "sst": [...],
    "ph": {...},              # 各章节的占位提示
    "seeds": {...},           # 术语、参考文件、试剂仪器、方法条件等预置行
}
```

最稳妥的做法是复制现有条目整体改写，不要凭记忆写结构。注意：

- 检查项的 `key` 在同一模板内必须唯一；
- **模板内容在创建方法时被复制进方法**，改模板只影响**之后新建**的方法；
- 改完后更新 `TEMPLATE_VERSION` 和该模板的 changelog，重启服务，新类型自动出现在“新建方法”里；
- 运行 `python tools\run_tests_report.py` 回归（`tests\test_templates.py`、`tests\test_projects.py` 检查各模板结构与预置内容，如需纳入新 key 请在这些测试里加入）；
- 引用的法规条款若不能确认原文，写“参见 xx 指南相应章节（条款待核对）”，不要编造条文号；
- 改动模板属于变更，请按企业变更控制记录。

阶段本身（9 个阶段、评审门、检查项）定义在同文件 `common_stages()`；改动它会影响所有新建方法，请谨慎。

## 14. 升级

1. 先关闭程序，做一次备份并复制到安全位置（`backup.bat`，加 `--files` 打包附件和文档；另存 `.audit_key` 和 `audit_head.json`）。

## 15. 常见问题

| 现象 | 处理 |
|---|---|
| 双击 `start.bat` 提示找不到 Python | 安装 Python 3.9+ 并勾选“Add python.exe to PATH”，或确认 Python 已加入 PATH（也可设置环境变量 `METHODFLOW_PYTHON`） |
| 提示缺少依赖 | 在 `start.bat` 提示时选 Y，或执行 `python -m pip install -r requirements.txt` |
| “Port 8780 is already in use” | 可能已有一个 MethodFlow 在运行（直接访问网址），或端口被占用：`python run.py --port 8790` |
| 浏览器没自动打开 | 手动访问窗口里显示的网址（默认 `http://127.0.0.1:8780/`） |
| 提示数据库是旧版本 | 见 11.2，用 `tools\migrate_v1_to_v2.py` 转换，转换前先备份 |
| 同事打不开 | 默认只监听本机；见第 12 节，并检查防火墙、IP 和 `allowed_hosts` |
| 局域网 HTTP 下登录后马上掉线 | 监听非本机地址时 Cookie 默认带 `Secure`；纯 HTTP 须设置 `"cookie_secure": false`，更好的办法是改用 HTTPS 反向代理 |
| “不允许的主机名”（HTTP 400） | 监听本机时只认 127.0.0.1/localhost；用域名访问或经反向代理时在 `allowed_hosts` 里加上该域名 |
| 初始化页要求“初始化口令” | `config.json` 设置了 `setup_token`，填入同样的值 |
| 账号被锁定 | 等待 `lock_minutes` 分钟，或让管理员重置口令（重置后首次登录须修改） |
| 管理员忘记口令 | 另一名管理员重置；没有其他管理员时用 `tools\reset_admin.py`（11.1） |
| “提交被阻止” | 页面会列出阻断原因：缺必填内容、前置阶段未通过、实验未关闭、没有可用复核人/批准人、FMEA 高风险无控制措施…… |
| “实验缺少设计或接受标准” / 新增实验被拒绝 | 开发方案提交或批准后，新增实验必须同时填写设计和接受标准；方案阶段复核时也会检查所有未取消的实验 |
| 签名时提示“内容已更新，请刷新后重新审阅” | 阶段内容在你打开页面后又变了，刷新、重新审阅后再签 |
| “版本冲突” | 他人已更新，刷新后重新修改 |
| 点“生成”后一直转圈 | 含 PDF 的生成需 20–60 秒；超过 `pdf_timeout_sec` 会放弃 PDF 只留 Word。仍无响应时检查是否有残留的 `soffice` 进程 |
| 没有 PDF，只有 Word | 未安装 LibreOffice / 路径不对 / `pdf_enabled=false` / 转换失败；页面会给出原因，见第 7 节 |
| 文档状态是“草稿” | 有阶段未通过或已失效，到文档页看列出的阶段；已失效的阶段用“重新提交复核”处理 |
| 文档状态是“完整性校验失败” | 已签署内容与签名时不一致，视为数据完整性事件，停止使用该文档并联系 QA 调查 |
| “文件丢失，请从备份恢复” | 附件/文档文件不在 `data\uploads` 或 `data\documents`；从 `files_*.zip` 或异地副本补回原位置 |
| 附件“校验完整性”失败 | 磁盘上的文件与上传时的哈希不一致，按企业流程调查 |
| 审计链校验失败 | 数据库记录被改动或损坏；保留现场，从备份恢复并通知 QA |
| 审计校验报“锚点缺失/被改动” | 恢复旧备份或拷贝数据库后常见；链校验通过时可用 `tools\audit_anchor.py --reset --yes` 重建 |
| 提示审计密钥缺失 | `data\.audit_key` 丢了，必须从备份取回，不能重新生成 |
| 生成的 Word 里中文字体不对 | 文档指定“微软雅黑/宋体”，目标电脑缺字体时由 Word 回退；图表字体取自本机已安装的中文字体 |

## 17. 局限与合规声明

- **本程序不是已验证的 GxP 系统：用于受监管用途须由企业 QA 按 CSV/GAMP 5 流程评估，补充 IQ/OQ/PQ、SOP、账号管理、备份与灾难恢复、电子签名法规符合性评估。**
- **模板中的数值（判据、样本量、限度、时间等）均为示例，须按本方法的 ATP 和产品知识确认**；系统只对未删去“示例值，须按ATP确认”标记发出警告，不判断数值是否合理。
- **模板和知识库里标“条款待核对”的法规/药典引用未经逐条核实原文**，使用前必须查阅现行版本确认。科学内容须由使用方专家评审。
- 本地账号体系，无 SSO/AD、无多因素认证、无口令过期；默认无 TLS（HTTP）。
- 时间取自服务器本机时钟，未与时间服务器同步，也不防时钟回拨。
- SQLite 单机单节点，无高可用；备份默认与数据同盘，需自行做异地备份，并单独保管 `.audit_key`。
- 审计哈希链（带密钥）和锚点只能**检测**数据库内的篡改，不能阻止同时拿到数据库和 `.audit_key` 的人重算整条链。
- 电子签名是程序内的“口令重新认证 + 修订/内容哈希绑定”，没有数字证书；项目与方法的团队角色由负责人指派，程序核对其与全局角色是否匹配，但账号与角色的合理性仍需管理制度保证。
- Word/PDF 文档无数字签名或写保护；PDF 依赖 LibreOffice 转换，版面可能与 Word 略有差异。
- 方法的验证、转移、常规使用等生命周期阶段 V0.2 只作为状态记录，没有对应的流程模板。
- 自动测试为开发者回归测试，界面没有自动化测试；不是 IQ/OQ/PQ。
- 完整缺口清单见 `docs\URS_需求与测试追溯.md`。

## V0.3 新增（2026-10-15）

- **按顺序走流程**：新建方法即启动第 1 步（向导里填写核心内容），后一步需前一步通过才开放；阶段页有“新手指引”，方法页有“下一步该做什么”卡片；左侧“新手指引”是整条流程的说明。
- **渐进补充**：核心内容缺失才阻断提交，其余只警示（配置 `strict_completeness=true` 可恢复全部必填）。
- **确认机制**：模板预置内容（FMEA、ATP 判据、RACI、术语等）须逐节“确认”才计为已填写；含“示例值”或“XX”占位符不能确认；方案提交前实验的示例判据须核对（实验页“确认示例值”）。含未确认内容的文档标为“待确认版”。
- **复核辅助**：复核人可查看与上一修订的对比；站内通知（右上角铃铛）；工作台列出可开始的下一步。
- **实验与计划**：批量启动/取消实验；重排计划；检查清单“全部标为完成”。
- **知识库资源链接**：知识库页 → “资源链接”，法规、监管机构、药典、文献、工具；可新增/编辑/停用；管理员可“检查链接有效性”。
- **界面语言**：右下角“中文 / EN”切换。模板正文、知识库条目和生成的文档目前仍为中文。
- **数据库结构 v4**：旧的 v3 库首次启动会原位升级，并先自动备份为 `data/backups/premigrate_v3_*.db`。
- 英文概览见仓库根目录的 `README.md`；未完成事项见 `ROADMAP.md`。

## V0.4 新增（2026-10-15，数据库结构 v5）

适用场景：个人单机与实验室局域网。不是已验证的 GxP 系统；`docs/CSV验证模板/` 给出验证起点（风险评估、IQ/OQ/PQ 清单、SOP 要点）。

- **结果自动判定 + 统计计算器 + CSV 导入**：结果行按判据（≥、≤、范围、±）自动给出“达标/不达标/待评价”，与人工判定不同在提交前警示；实验页“统计计算器”可做描述统计、准确度、精密度（ANOVA）、线性、LOD/LOQ、等效性（TOST）、计数 CV，并一键写入结果表；“导入 CSV”追加结果行。
- **台账（顶部导航“台账”）**：试剂/材料与仪器/设备的批号、效期、校准到期日；到期/校准过期自动在运行记录上警示。
- **运行记录**（实验页）：日期、分析员、使用的材料与仪器、结果状态；需第二人核对。
- **偏离记录**（方法页“偏离”）：未关闭的“主要/严重”偏离阻止其所属步骤提交；关闭是电子签名，不能由提出人关闭，主要/严重须批准人。
- **审计追踪审核**（管理 → 审计追踪审核）：记录谁、何时、审核了哪段审计追踪，同时校验哈希链与全部签名；逾期提醒（`audit_review_days`，默认 90 天）。
- **检查包**（方法页“检查包”）：一个 zip，含内容、实验、运行、偏离、签名清单、审计追踪、附件与哈希清单、已生成文档。
- **评论与 @提醒**（阶段页每节的 💬）、**全局搜索**（顶部搜索框）、**已批准方法的修订版**（保留旧版并记录变更说明）。
- **密码有效期与历史**（`password_max_days`、`password_history`）；可选“修改原因”（`require_change_reason`，记入审计）。
- **文档**：后台生成（带进度）；“文档语言”可选 English——封面、表头、章节标题、签署页等固定文字为英文，模板正文与用户填写内容保持原样。
- **邮件 / Webhook 通知**：在 `config.json` 配置 `smtp_*` 或 `webhook_url`（企业微信/钉钉/飞书等，`webhook_kind`）；用户在右上角菜单“设置我的邮箱”。
- **数据库结构 v5**：旧 v3/v4 库首次启动原位升级，并先备份为 `data/backups/premigrate_v*_*.db`。
- 开源配套：`LICENSE`、`NOTICE`、`CONTRIBUTING.md`、`SECURITY.md`、`.github/workflows/test.yml`。
- 留给社区：验证/转移/常规监控完整模块、网页模板编辑器、存量方法导入、CTD 生成、4PL/平行性、SSO/PostgreSQL/Docker、培训资质矩阵、模板正文英文翻译。
