# MethodFlow 前端模块契约（数据模型 v2：项目 / 方法分离）

静态文件目录：`app\static\`。无构建工具，原生 JS（ES2017，不用 import/export，不依赖 CDN，离线可用）。
`index.html` 按顺序加载各 `*.js`（文件划分由前端自行决定；下文“负责模块”仅为建议）。所有模块把东西挂在全局 `window.MF` 上；界面文字全部中文。

> V0.2 起：**项目（Project）= 产品/管线层面的容器**；**方法（Method）= 一个具体分析方法**，9 阶段开发流程、实验、附件、评审、审计、文档全部属于方法。
> 旧的 `/api/projects/{pid}/stages|experiments|attachments|audit|kb|docs|export|members|clone` **已删除**，一律改为 `/api/methods/{mid}/…`（`/api/projects/{pid}/audit` 与 `…/members` 现在是**项目级**接口，含义不同）；
> 旧路由 `#/p/...` 不再保留。本文第 2、3 节是后端的**精确**接口说明（字段名、类型、错误码均以 `tests\` 为准）。

## 1. core.js（提供者：核心代理；本节与 V0.1 相同，仅示例路径更新）

| `/m/:mid/audit` | 方法审计日志 | `GET /api/methods/{mid}/audit` |

方法页共同头部：编号 `AM-…`、名称、所属项目（`project.code`/`project.name`，链接到 `/pr/:pid`）、模板标签（`technique_label` + `template_version`）、生命周期徽标（`lifecycle_label`）、方法版本（`method_version`）、开发状态（`status_label`）、总进度、标签页（总览/阶段/实验/文档/审计/知识）。
阶段页内容由 `MF.renderStage(container, mid, key, method)` 渲染（`method` 为 `GET /api/methods/{mid}` 的返回对象）；阶段页自行调接口并在操作后重新渲染自己；若影响整个方法（提交/复核/重新打开）则同时调用 `MF.reload()`。
所有“可做什么”以接口返回的布尔字段为准（`permissions.*`、`stage.editable/can_submit/can_withdraw/can_reopen/can_recertify/can_sign_as`），不要在前端重算权限。

## 3. 后端接口（v2，逐项精确）

通用约定：JSON；所有非 GET 请求须带请求头 `X-Requested-With: MethodFlow`（否则 403）；未登录 401；错误体一律 `{"error": 文字, "detail": …}`（`detail` 多为 `null`；提交被阻断时为 `{"blocks":[…],"warns":[…]}`）；`must_change` 用户只能调用 `/api/me`、`/api/me/password`、`/api/logout`，其余 403 `{"error":"须先修改密码","must_change":true}`。时间均为 UTC ISO（`2026-10-14T08:15:30Z`），日期为 `YYYY-MM-DD`。请求体中的整数 id 必须是 JSON 整数（字符串 → 400）。

### 3.1 角色与权限（前端据此决定显示什么）

**全局角色**（`user.roles`）：`admin` `author`(开发人员) `reviewer`(复核人) `approver`(批准人 QA) `viewer`(只读)。
**项目角色**（`GET /api/projects/{pid}` 的 `my_roles`、`members[].role`）：`owner`(项目负责人) `member`(项目成员) `viewer`(只读)。一人在一个项目里只有一个项目角色。
**方法角色**（方法接口的 `my_roles`、`members[].role`）：`owner`(方法负责人) `author`(开发人员) `reviewer`(复核人) `approver`(批准人 QA) `viewer`(只读)；一人可有多个方法角色。

| 动作 | 谁可以 |
|---|---|
| 新建项目 | 全局 `author` 或 `admin`（创建者自动成为项目负责人） |
| 修改项目信息/状态、调整项目团队 | 项目负责人 |
| 查看项目 | 项目成员（任意项目角色）∪ 管理员 |
| 新增方法 / 克隆方法到某项目 | 该项目的负责人或成员（`owner`/`member`，**不含项目只读成员**）且全局 `author`/`admin`；项目须“进行中” |
| **查看方法**（阶段、实验、附件、审计、知识、文档列表与下载、导出、作为克隆源） | 方法成员 ∪ 其所属项目的任意成员 ∪ 管理员 |
| **编辑内容**（保存阶段、实验、上传附件、提交/撤回、登记经验） | **仅方法角色** `owner`/`author` |
| 复核/批准（签名） | **仅方法角色** `reviewer`/`approver`，且满足全部职责分离规则（见 3.9） |
| 重新打开已通过阶段 | 方法 `owner` 或 `approver`（原因 + 口令） |
| 修改方法信息/状态 | 方法 `owner` |
| 调整方法团队 | 方法 `owner` **或**所属项目的负责人 |
| 变更方法生命周期 | 方法 `owner` 或 `approver`（原因 + 口令） |
| 生成文档 | 方法角色 `owner`/`author`/`reviewer`/`approver` 或管理员 |
| 成为方法成员 | 必须是所属项目成员（**管理员除外**），且方法角色匹配其全局角色 |

写操作（保存/提交/撤回/复核/重开/实验/附件/方法团队）额外要求**方法与所属项目都是“进行中”**，否则 409（`方法已归档，不可修改` / `所属项目已暂停，不可修改`）；读取、生成文档、登记经验、变更生命周期、修改方法/项目信息与状态不受此限。

### 3.3 工作台 `GET /api/dashboard`
```
{ projects:  [ <项目行> ... ],                      // 我是成员的项目（管理员：全部），按最近更新排序
  methods:   [ <方法行> ... ],                      // 我能看到的方法（方法成员 ∪ 项目成员；管理员：全部）
  to_review: [ {method_id, method_code, method, project_code, stage_key, stage, role, role_label} ],
                                                   // role = reviewer / approver（我现在可以签署），或 "stale"（role_label=“已失效，需重新提交复核”，方法团队成员的待办）
  my_stages: [ {method_id, method_code, method, project_code, stage_key, stage, status, status_label, planned_end, overdue} ],
  my_experiments: [ {id, method_id, code, method_code, method, project_code, title, status, status_label, planned_end, overdue} ] }
```
`code` 是**实验**编号，`method_code` 是方法编号 `AM-…`，`method` 是方法名称，`project_code` 是项目编号 `PRJ-…`。`to_review`/`my_stages`/`my_experiments` 只包含“方法与项目均为进行中”的条目。

**项目行**（`GET /api/projects` 每项；`GET /api/projects/{pid}` 以此为基础；dashboard.projects 同）：
`{id, code:"PRJ-2026-001", name, product, indication, phase, description, status, status_label, planned_start, planned_end, owner_id, owner_name, created_at, updated_at, my_roles:[项目角色], method_count, progress, overdue:[方法编号], stale:[方法编号]}`
`status` ∈ `active`(进行中) `paused`(暂停) `completed`(完成) `archived`(归档)。`progress` = 项目下未取消方法的平均进度（0–100，无方法为 0）；`overdue`/`stale` 是含逾期阶段/失效阶段的（未取消）方法的编号列表。`planned_start/planned_end` 可为 `null`。

**方法行**（`GET /api/methods`、`GET /api/projects/{pid}/methods`、dashboard.methods 同）：
```
{id, code:"AM-2026-001", name, project_id, project_code, project_name,
 technique:"flow",                  // 模板 key（筛选参数 technique 用它）
 technique_label:"流式细胞术（…）", template_version:"1.1",
 analyte, matrix, intended_use, phase, method_version:"V0.1",
 lifecycle, lifecycle_label,        // development(开发) validation(验证) transfer(转移) routine(常规使用) retired(停用)
 status, status_label,              // active(进行中) completed(完成) archived(归档) cancelled(取消)
 planned_start, planned_end, owner_id, owner_name, updated_at,
 my_roles:[方法角色], my_project_roles:[项目角色],
 progress:0-100, current_stage:{key,title,status}|null,   // 第一个未通过/未完成的阶段；全部完成为 null
 overdue:[逾期阶段标题], stale:[失效阶段标题]}           // 方法不是进行中时 overdue 恒为空
```
`GET /api/projects/{pid}/methods` 的每行另有 `signatures_ok`（该方法全部已签署阶段的签名是否完好；false 时在清单里给“完整性校验失败”提示）。

### 3.4 项目
| 接口 | 请求 | 返回 / 规则 |
|---|---|---|
| `GET /api/projects?q=&status=` | `q` 匹配编号/名称/产品/适应症（不区分大小写）；`status` 精确匹配 | `[项目行]`；只含我是成员的项目（管理员：全部） |
| `POST /api/projects` | `{name*, product?, indication?, phase?, description?, planned_start?, planned_end?, members?:[{user_id, role:"owner"\|"member"\|"viewer"}]}` | `{id}`。全局 `author`/`admin` 才可（403）。创建者自动为 `owner`。`owner` 须具备全局 `author`/`admin`；同一人列多个角色取最高；`name` 必填 ≤200；日期 `YYYY-MM-DD` 且结束不早于开始；非法 400 |
| `GET /api/projects/{pid}` | | 项目行 + `members:[{user_id, role, role_label, display_name, username, active}]` + `permissions:{can_edit, can_manage_members, can_create_method}`；非成员 403，不存在 404（管理员） |
| `PATCH /api/projects/{pid}` | 任意子集：`name product indication phase description planned_start planned_end status`，另可带 `reason`、`password` | `{ok:true}`。仅项目负责人（403）。`status` ∈ active/paused/completed/archived（其他 400）；改为 `completed` 要求项目下没有“进行中”的方法（422）；**把非 active 的项目改回 `active` 须带 `reason`（缺 → 400）与 `password`（缺/错 → 403）**；项目下任一方法的任一阶段已批准/完成后 `product` 冻结（409） |
| `PUT /api/projects/{pid}/members` | `{members:[{user_id, role}]}`（**整体替换**） | `{ok:true}`。仅项目负责人（403）；项目须进行中（409）；至少保留一名 `owner`（400）；仍在某方法团队里的人不能移出项目（409，文字列出“姓名（方法编号）”） |
| `GET /api/projects/{pid}/methods` | | `[方法行 + signatures_ok]`（项目成员/管理员可见项目下全部方法） |
| `POST /api/projects/{pid}/methods` | `{name*, template_key?("generic"；也接受别名 technique), analyte?, matrix?, intended_use?, phase?, method_version?("V0.1"), planned_start?(默认今天), members?:[{user_id, role:方法角色}]}` | `{id}`（方法 id）。须项目 `owner`/`member` 且全局 `author`/`admin`（403）；项目须进行中（409）；创建者自动成为方法 `owner`+`author`；`members` 须是项目成员（管理员除外）并满足 3.9 第 7 条（400）；自动建 9 个阶段、预置模板内容、实验种子；编号 `AM-YYYY-NNN`（全局序号） |
| `GET /api/projects/{pid}/audit?limit=300` | `limit` 夹到 [1,2000] | 项目级聚合审计：项目本身及其全部方法的记录，按 id 倒序；行结构见 3.8；项目成员/管理员可见 |

### 3.5 方法
| 接口 | 请求 | 返回 / 规则 |
|---|---|---|
| `GET /api/methods` | 查询参数均可选：`q`（编号/名称/被测属性/样品基质/所属项目编号与名称，不区分大小写）、`status`、`project_id`（整数）、`technique`（模板 key）、`lifecycle` | `[方法行]`，只含我能看到的方法，按最近更新排序 |
| `GET /api/methods/{mid}` | | 见下“方法详情”；无权 403，不存在 404（管理员） |
| `PATCH /api/methods/{mid}` | 子集：`name analyte matrix intended_use phase method_version planned_start planned_end status`，另可带 `reason`、`password` | `{ok:true}`。仅方法 `owner`（403）。`status` ∈ active/completed/archived/cancelled；`completed` 要求全部阶段已通过/完成且无失效（422）；**非 active → active 须 `reason`(400) + `password`(403)**；**任一阶段已批准/完成后 `name/analyte/matrix/intended_use` 冻结（409）**；传 `lifecycle`/`project_id`/`template_key`/`technique`/`code` 且与当前值不同 → 400（生命周期请用 `/lifecycle`；与当前值相同则忽略） |
| `PUT /api/methods/{mid}/members` | `{members:[{user_id, role}]}`（**整体替换**） | `{ok:true}`。方法 `owner` 或所属项目负责人（403）；方法与项目须进行中（409）；至少一名方法 `owner`（400）；成员须是项目成员（管理员除外）、角色匹配全局角色、职责分离（400）；有阶段待复核时不能增删复核人/批准人（409） |
| `POST /api/methods/{mid}/clone` | `{title?, project_id?}` | `{id}`（新方法）。全局 `author`/`admin`（403）；源方法须可见（403）；`project_id` 缺省为源方法所属项目，目标项目的规则同“新增方法”（非成员/只读成员 403，非进行中 409，不存在 404）；`title` 或 `project_id` 类型错 400。新方法：名称默认“原名（副本）”，复制被测属性/基质/用途/阶段与各章节内容（以当前模板结构为准），检查清单重置为未完成；**不复制签名、团队（只有创建者）、实验及结果** |
| `POST /api/methods/{mid}/lifecycle` | `{lifecycle, reason, password}` | `{ok:true}`。方法 `owner`/`approver`（403）；`lifecycle` ∈ development/validation/transfer/routine/retired（400），与当前相同也 400；`reason` 非空（400）；`password` 重新认证（缺/错 403）；**写审计 `method.lifecycle`（details `{from,to}`，reason）**；方法处于任何开发状态都允许 |

### 3.6 阶段（路径 `/api/methods/{mid}/stages/{key}…`，key ∈ charter atp tech risk plan explore robust control report）
| 接口 | 请求 | 返回 / 规则 |
|---|---|---|
| `GET …/stages/{key}` | | **阶段详情**（见下） |
| `PUT …/stages/{key}` | `{version(必填整数), sections?:{章节key:值}, checklist?:{项key:{status:"todo"\|"done"\|"na", note}}, planned_start?, planned_end?}` | 阶段详情。仅方法 `owner`/`author`（403）；乐观并发（`version` 不符 409）；阶段不可编辑或方法/项目非进行中 409；只发改动的章节；类型/结构不符 400（FMEA 的 S/O/D 须 1–10 整数或空） |
| `GET …/stages/{key}/checks` | | `{blocks:[文字], warns:[文字]}`（提交前检查；见 3.7） |
| `POST …/stages/{key}/submit` | `{comment?}` | `{ok:true}`；不满足条件 422 `detail={blocks,warns}` |
| `POST …/stages/{key}/withdraw` | `{reason}` | `{ok:true}`（待复核 → 进行中，修订号+1） |
| `POST …/stages/{key}/review` | `{decision:"approve"\|"reject", comment?, password, revision, expected_hash}` | `{ok:true}`。`revision` 与 `expected_hash` 必须取自该次阅览的阶段详情（缺失/类型错 400；不符 409“内容已更新，请刷新后重新审阅”）；退回须 `comment`；口令错 403 |
| `POST …/stages/{key}/reopen` | `{reason, password}` | `{ok:true, affected:[{stage, effect}]}` |
| `POST …/stages/{key}/recertify` | `{comment?}` | `{ok:true}`（失效阶段重新提交复核） |

**阶段详情**字段：`id, method_id, key, ord, def(模板定义: title, desc, sections[], checklist[], gate, requires, weeks…), status, revision, version, stale, data:{sections:{章节key:值}, checklist:{项key:{status,note,by,at}}}, editors[用户id], contributors[用户id], planned_start, planned_end, actual_start, actual_end, submitted_at, updated_at, title`；
附加：`method:{id, code, name, status, lifecycle}`、`project:{id, code, name}`、`status_label, progress, checks:{blocks,warns}, next_role, can_sign_as, cannot_sign_reason, editable, can_submit, can_withdraw, can_reopen, can_recertify, reviews:[{id, revision, role, role_label, decision, comment, signed_at, data_hash, meaning, display_name, intact}], revisions:[{revision, data_hash, created_at}], hash, experiments:[实验], attachments:[附件], editor_names[], contributors_names[], signatures_ok, signature_problems[文字]`。
`editable` 已综合“方法角色 + 阶段状态 + 方法/项目进行中”；`hash` 即签名要绑定的内容哈希。

模板章节（`def.sections[]`）类型：`text / fields / table / matrix / fmea`；模板 1.1 起每个章节另有 `ch:{plan:"6.4", report:"7.4"}`（在两份受控文件中的章号，可在标题旁显示“对应方案 6.4 / 报告 7.4”）、文本章节有 `placeholder`/`help`/`default`，表格章节有 `seed_rows`（仅供新建方法时预置，用户数据在 `data.sections` 里）。checklist 项含 `key, text, guidance, ref, required, evidence`（`evidence=true` 的项标记 `done` 时**必须**填 `note`，否则提交被阻断）。

### 3.7 模板预置与提示
* 新建/克隆方法时，每个带 `seed_rows` 的表格章节以其种子行预置，每个带 `default` 的文本章节以默认正文预置；ATP 判据、技术评分矩阵、FMEA、SST、实验（接受标准带 `（示例值，须按ATP确认）` 标记）照旧预置。
* **示例值警告**：`plan` 与 `report` 阶段的 `checks.warns`（及提交时的 `warns`）在该阶段数据（含其评审门所覆盖的阶段）或未取消实验的 `acceptance` 中仍含“示例值，须按ATP确认”时给出一条警告（含数量）。**只是警告，不阻断提交。**前端应醒目显示，并提示“按 ATP 确认后删去标记”。

**文档（V0.4：Word + PDF）**
- `POST /api/methods/{mid}/docs` `{kind:"plan"|"report"}` → `{gen_id, docs:[{id, format:"docx"|"pdf", filename}], pdf_available:boolean, pdf_note:string, id, filename}`。一次生成同时产出 Word 与（可能的）PDF：`docs[0]` 恒为 `.docx`；PDF 与它**同名不同扩展名**；`pdf_available=false` 时 `docs` 只有 `.docx`，`pdf_note` 说明原因（未安装 LibreOffice / 转换失败 / 超时 / 配置关闭），界面应提示但不视为错误。`id`、`filename`（= `.docx`）仅为兼容旧客户端保留。权限：方法角色 owner/author/reviewer/approver 或管理员，否则 403；每方法每分钟最多 6 次**生成**（两种格式算一次），429；未知 `kind` 400；生成期间方法数据变化 409（请重试）。生成一份约 20–60 页的文档含 PDF 转换需 10–40 秒，按钮应显示进行中状态。
- `GET /api/methods/{mid}/docs` → 数组，**每个文件一行**，新的生成在前，同一次生成内 `.docx` 在前：`{id, gen_id, kind, format, filename, version_label, status_label, data_hash, created_at, display_name, file_sha256, generated_signatures_ok, signatures_ok, bad_signatures[]}`。`gen_id` 相同的行属于同一次生成（= 该次 `.docx` 行的 id；旧记录 `gen_id = id`）；`version_label` 如 `V2`（同方法同类型的第几份）；`status_label` ∈ “草稿（含未复核内容）” / “已批准版本” / “完整性校验失败”（生成当时的状态）；`signatures_ok` 为**当前**签名完整性，`generated_signatures_ok` 为生成当时的；`file_sha256` 是文件本身的 SHA-256（旧记录为 null）；`data_hash` 是来源数据哈希。界面可按 `gen_id` 分组，每组显示“下载 Word / 下载 PDF”。
- `GET /api/docs/{did}/download`：不变；`.docx` 为 `application/vnd.openxmlformats-officedocument.wordprocessingml.document`，`.pdf` 为 `application/pdf`；权限同方法可见性。
- `GET /api/system/capabilities`（任何登录用户）→ `{pdf:boolean, pdf_note:string}`：服务器当前能否生成 PDF；`pdf=false` 时界面应把“PDF”提示置灰并显示 `pdf_note`（安装方法）。
- `GET /api/admin/settings`（仅管理员，否则 403）→ `{company_name, footer_text, doc_prefix, soffice_path, pdf_available, pdf_note, soffice_found, defaults:{…}}`；`soffice_found` 为实际会使用的 soffice 路径（空串 = 未找到）。`footer_text` 默认“打印件未经控制”，其余默认空串。
- `PUT /api/admin/settings`（仅管理员）体为以下键的任意子集：`company_name`(≤100) `footer_text`(≤200) `doc_prefix`(≤20，仅字母数字及 `. _ / -`，加在文件编号前，如 `QC-` → `QC-AM-2026-001-PLAN-V1`) `soffice_path`(≤500；空串 = 自动查找，非空须是存在的 `soffice` / `soffice.exe` 文件)；值必须是文本，否则 400（含未知键）；返回同 GET；有变化时写审计 `settings.update`（`details.changes`）。
- 文件编号规则：`[doc_prefix]方法编号-PLAN-Vn`（方案）/ `…-RPT-Vn`（报告）。系统设置页建议放在 `/admin`，保存后立即对之后生成的文档生效。

**管理**：`POST /api/admin/backup` → `{name}`；`GET /api/admin/backups` → `[{name,size,mtime,manifest}]`；`POST /api/admin/kb-sync`（见上）。

### 3.9 沿用的加固规则（V0.1 后端加固，现按**方法**计）
1. `POST …/stages/{key}/review` 必须带 `revision`（整数）与 `expected_hash`（字符串），取自该次阅览的阶段详情；缺失/类型错误 400；与服务器当前值不符 409 `内容已更新，请刷新后重新审阅`。
2. 阶段详情的 `contributors`（累计的贡献者用户 id）、`contributors_names`、`signatures_ok`、`signature_problems`；`reviews[].intact` = 签名完好（含实验/附件/方法与项目信息，历史修订对照快照）。`editors` 仍是当前修订的编辑者。贡献者（保存人、提交人、实验编辑人、实验附件上传/删除人）永不得复核/批准该阶段。
3. 方法详情、导出、文档列表带 `signatures_ok`/`bad_signatures`；`GET /api/audit/verify` 见 3.8。
4. 登录：错误用户名/口令 401 `用户名或密码错误`；锁定 423 `登录尝试过多，请稍后再试`；同一用户名+IP 每分钟失败过多 429；停用账号且口令正确 403。改密码成功后其他会话失效；旧口令错误计入失败次数（400，第 5 次后 423）。
5. **非“进行中”的方法或项目的写操作 409**；方法/项目状态改回 `active` 须 `reason` + `password`。已批准/完成阶段后，方法的 `name/analyte/matrix/intended_use` 与项目的 `product` 不可改（409）。
6. 实验：方案提交/批准后，方案内实验的 `title/objective/design/acceptance/stage_key` 修改 409、删除 409（提示重新打开方案阶段）；`stage_key` 一旦设置不可置空（409），改派目标须存在（404）且未锁定（409）；其后新增的实验 `added_after_plan=1`，文档中单列。
7. **团队规则**（`POST …/methods` 与 `PUT /api/methods/{mid}/members`，违反 400/409）：方法角色须匹配全局角色（owner/author 需全局 author 或 admin，reviewer/approver 需对应全局角色）；成员须是项目成员（管理员除外）；同一人不能同时是（owner/author）与（reviewer/approver）；reviewer 与 approver 不能是同一人；至少一名方法 owner；有阶段待复核时不能增删 reviewer/approver。前端选择候选人时应按“项目成员 + 全局角色”过滤。
8. 保存阶段时 `sections`/`checklist`/日期按模板定义校验（400）；FMEA 的 S/O/D 必须是 1–10 整数或留空，界面应在输入处拦截。
9. 上传：超过大小限制 413；其余 JSON 接口请求体上限 20 MB（413）。
10. `POST /api/setup`：若部署配置了 `setup_token`，须带同名字段（`/api/state` 的 `setup_token_required` 为 true 时界面多一个输入框）。
11. 旧版（项目 = 方法，结构版本 1/2）数据库不能直接启动，程序给出提示；用 `tools\migrate_v1_to_v2.py` 转换（每个旧项目变成一个方法，并自动建同名项目）。
